Open source · Windows, Linux and macOS

Reproducible dev VMs, grown from one YAML file.

Vmynt builds fully provisioned Linux desktop VMs for development: GNOME, git, Node, Python, Docker, ddev, VS Code, Chrome and Postgres, with your repositories already cloned. Describe the machine once in a config file you commit with your project, and everyone on the team gets the same box from one command.

It works like ddev: run vmynt init in any folder, then start, stop, open and list your VMs from anywhere. One CLI drives Hyper-V on Windows, KVM on Linux and Apple Virtualization on macOS.

Three commands to a desktop. vmynt init writes the config, vmynt create builds the VM, vmynt open opens it. Vmynt is 0.x: Linux has a nightly end-to-end build, and Hyper-V and macOS get their first real-hardware pass before 1.0. See the roadmap.

What you get

A real dev desktop

GNOME with git, Node (nvm), Python, Docker, ddev, VS Code and its extensions, Chrome, and optional Postman and remote access tools. Or go headless with Ubuntu Server.

Your project, ready

Repositories cloned, a GitHub SSH key set up, dotfiles applied, files copied in and post-start hooks run, all on first boot.

Databases included

Postgres or MySQL with the databases you name, plus Adminer at http://<host>.local:3800 to browse them.

Config you can commit

Shared settings live in .vmynt/vm.config.yaml. Your username and password hash stay in a git-ignored local file.

ddev-style CLI

init, create, start, stop, open, ssh, list, snapshot, from any folder. Shell completion, --json, and help for every command.

One CLI, three hosts

Hyper-V on Windows, KVM through libvirt on Linux, and Apple Virtualization through vfkit on macOS, on x86_64 and arm64.

Reachable by name

Every VM announces itself over mDNS, so it is http://<host>.local from your machine and from the other VMs.

Your own blueprints

Five Linux blueprints are built in. Copy one into your project with vmynt blueprints new and change anything.

How it works

  1. Set up the project vmynt init asks for a project name, a blueprint and your user, then writes a .vmynt/ folder with the config files.
  2. Build the VM vmynt create downloads and verifies the OS installer, installs it unattended, and provisions everything in your config on first boot.
  3. Open it vmynt open starts the VM if needed and opens its desktop. vmynt ssh for a shell, vmynt list to see every VM on your machine.

Install

One self-contained program. You don't need Rust, PowerShell or anything else to run it, just the hypervisor for your system.

PowerShell
winget install CodeScarlett.Vmynt

Or with Chocolatey: choco install vmynt

terminal
brew install scarlettiron/tap/vmynt
Debian / Ubuntu
curl -fsSL https://scarlettiron.github.io/vmynt/apt/vmynt-archive-keyring.gpg | sudo tee /usr/share/keyrings/vmynt-archive-keyring.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/vmynt-archive-keyring.gpg] https://scarlettiron.github.io/vmynt/apt stable main" | sudo tee /etc/apt/sources.list.d/vmynt.list
sudo apt update && sudo apt install vmynt

Any other distribution: brew install scarlettiron/tap/vmynt, or a download from GitHub Releases.

Questions

Does Vmynt build VMs today?

Yes. vmynt create downloads and verifies the install ISO, installs the OS unattended and provisions it, and start, stop, open, ssh, exec, logs, status, list and snapshot manage it afterwards, on Hyper-V, KVM through libvirt and Apple Virtualization. Vmynt is still 0.x: Linux has a nightly end-to-end build in CI, and Hyper-V and macOS get their first real-hardware pass before 1.0.

Do I need Rust or PowerShell installed?

No. Vmynt is a single self-contained program. Install it with winget, Chocolatey, Homebrew or apt, or download it from GitHub Releases. The only other thing it needs is the hypervisor for your system.

Which operating systems can the VMs run?

Linux. The built-in blueprints are Rocky Linux, Red Hat Enterprise Linux, Fedora, Ubuntu Desktop and Ubuntu Server. The host can be Windows, macOS or Linux; Windows guests are not planned for 1.0.

Where do the VM disks go?

Out of your project, so cloud sync and backups never pick up 25 GB disk files: in ~/.vmynt/vms/ on Windows and macOS (vm.path moves them), and in a libvirt storage pool on Linux (/var/lib/libvirt/images by default, set with vm.storagePool), because the system QEMU can't read home folders.

Is my password stored in the config?

No. vmynt init hashes it straight away (SHA-512 crypt) and writes only the hash to vm.config.local.yaml, which is git-ignored.

What does it cost?

Nothing. Vmynt is open source under the MIT License.
