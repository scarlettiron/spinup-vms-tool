Vmynt / Commands

Command reference

Every vmynt command, its aliases and its options. Run vmynt help <command> for the same detail in your terminal.

Every command works on all three hypervisors: Hyper-V on Windows, KVM through libvirt on Linux, and Apple Virtualization through vfkit on macOS. Where a backend differs, the command says so below.

usage
vmynt <command> [name] [options]

Global options

These work with every command.

-h, --help
Help for Vmynt, or for the command it follows.
-v, -V, --version
Print the version. (-v is the version, so verbose output has no short flag.)
--verbose
More detail, and the full chain of causes on errors.
-q, --quiet
Only print errors.
--json
Machine-readable output, for list, status, config, version and blueprints. The JSON shape is stable; the human output may change.
--no-color
Plain output. The NO_COLOR environment variable does the same. Color is only used when printing to a terminal.
-y, --yes
Don't ask for confirmation. Without it, destructive commands refuse to run when there is no terminal to ask in.

--all is not global: it belongs to the commands that act on several VMs (start, stop, restart, remove, status, and create, where it means every machine of the current project), so it never shows up on a command that would ignore it.

Mistype a command and Vmynt suggests the closest one: vmynt strat asks if you meant start.

Choosing a VM

  1. vmynt <command> <name>: the VM, machine or hostname with that name, from any folder.
  2. vmynt <command> inside a project: that project's VM, or all of its machines. open, ssh, exec, logs and snapshot need one VM and ask you to name it when there are several.
  3. --all: every VM Vmynt built on this computer.

Exit codes

CodeMeans
0Success
1The command failed
2Usage error: unknown command, option or value
3The VM or project was not found

vmynt init

available

Create the .vmynt/ config in the current folder.

usage
vmynt init [--name <name>] [--blueprint <name>] [options]
--name <name>
Project name. Default: the folder name. Must be hostname-safe.
--blueprint <name>
Blueprint to use. Without it, init shows a list, including Create my own….
--username <name>
Primary user in the VM.
--password-hash <hash>
A SHA-512 crypt hash, as made by vmynt hash. Without it, init asks for a password and hashes it.
--no-user
Skip the user questions; fill in vm.config.local.yaml later.
--import <path>
Copy vm.config.yaml and vm.config.local.yaml from another project, or from an old checkout of the PowerShell tool.
--force
Run even though .vmynt/ exists. Rewrites the example files only; never touches your local file.
-y, --yes
Accept defaults. With no terminal, a missing answer is an error.

See How init works.

vmynt config

available

Show the merged configuration for the current project, after every layer is applied.

usage
vmynt config [--machine name] [--validate] [--json]
--machine
Show the config for one entry of the machines: block.
--validate
Run every check create runs: unknown keys (with suggestions), ranges, blueprint and OS version, data disks, database, files to copy, hooks, repos and SSH keys. A missing user is a warning here and an error for create.
--json
Print the merged config as JSON.

vmynt create

available

Aliases: new, build

Build the VM from config: download and verify the installer, install unattended, provision on first boot.

usage
vmynt create [name] [--render] [--force] [--no-checkpoint] [--all]
--render
Render the seed files into the VM's build/ folder for review, without touching the hypervisor or downloading anything.
--force
Delete and rebuild the VM if one with that name already exists. Without it, create refuses (exit 2).
--no-checkpoint
Skip the clean-install snapshot taken after the OS install.
--all
Build every machine of the project in this folder.

Prints numbered steps on stderr (plan, name check, install media, seed disk, define, install, finish, checkpoint), so --json output stays clean. See what create does.

vmynt start

available

Aliases: up

Start or resume a VM. Never provisions: use create for that.

usage
vmynt start [name] [--all]

Waits up to three minutes for the VM to have a network address, and prints its URL.

vmynt stop

available

Aliases: halt, down

Shut the VM down and free its memory. Keeps the disks.

usage
vmynt stop [name] [--save] [--force] [--all]
--save
Save the VM's memory to disk (hibernate) instead of shutting down. Not available on macOS.
--force
Turn it off without a clean shutdown.

A clean shutdown waits up to two minutes, then says how to force it.

vmynt restart

available

Stop, then start.

usage
vmynt restart [name] [--all]

vmynt poweroff

available

Shut down every running VM Vmynt built on this computer, to get the memory back.

usage
vmynt poweroff

vmynt remove

available

Aliases: rm, destroy

Delete the VM and its record. Disks are kept unless you ask. Always asks first; without a terminal it needs --yes.

usage
vmynt remove [name] [--delete-disks] [-y]
--delete-disks
Delete the VM's disks too.
-y, --yes
Don't ask for confirmation.

vmynt open

available

Aliases: desktop, console

Start the VM if needed, wait for its desktop, and open it.

usage
vmynt open [name] [--console] [--no-wait]
--console
Open the raw console instead of the desktop: vmconnect on Windows, virt-viewer on Linux. On macOS a console window exists only for a VM started with one, so stop it first and open --console starts it with a window.
--no-wait
Open straight away instead of waiting (up to four minutes) for the guest to be ready.

The desktop opens in vmconnect (Enhanced Session) on Windows, Microsoft's Windows App on macOS, and FreeRDP or Remmina on Linux.

vmynt ssh

available

Open an interactive shell in the VM with your system's ssh. Vmynt adds its own key to every VM it builds, so this works with no setup.

usage
vmynt ssh [name]

vmynt exec

available

Run one command in the VM and print its output. The exit code is the command's own.

usage
vmynt exec [-n name] -- <command…>
-n, --name
The VM or machine (default: the project in this folder).

vmynt logs

available

Show the provisioning (bootstrap) and post-start logs from inside the VM.

usage
vmynt logs [name] [-f] [-n lines]
-f, --follow
Keep printing new lines as they arrive.
-n, --lines
How many lines to show from the end (default 100).

vmynt list

available

Aliases: ls

Every Vmynt VM on this computer: name, status, blueprint, URL, Adminer and project folder.

usage
vmynt list [--live] [--rescan] [--json]
--live
Also connect to every running VM at once and add DATABASE and BOOTSTRAP columns.
--rescan
Rebuild the project list and VM records from the tags Vmynt puts on each VM in the hypervisor, for when ~/.vmynt was lost.
--json
Output for scripts.

STATUS comes from the hypervisor: running, stopped, saved, paused or not created; missing means the project folder is gone.

vmynt status

available

Aliases: info, describe

Full detail for one VM: OS, kernel, address, ssh line, users, hardware, disks and usage, database, Adminer, hooks, GitHub access and provisioning progress.

usage
vmynt status [name] [--follow] [--no-ssh] [--report] [--all] [--json]
--follow
Redraw every 10 seconds until provisioning completes or fails.
--no-ssh
Only report what the hypervisor knows; don't connect to the VM.
--report
Also print the guest's own bootstrap report: every step and its result.
--json
One object (an array for several VMs) with state, url, ip, bootstrap (complete, failed, progress or unknown), database, adminer and more.

vmynt snapshot

available

Save and restore points in a VM's life.

usage
vmynt snapshot create <label> [name]
vmynt snapshot list [name]
vmynt snapshot restore <label> [name]
vmynt snapshot delete <label> [name]
create <label>
Take a snapshot. Labels are letters, digits, dots, dashes and underscores. On Linux and macOS the VM must be stopped.
list
List snapshots (alias ls). create takes one called clean-install after the OS install.
restore <label>
Go back to a snapshot. Asks first unless -y.
delete <label>
Delete a snapshot (alias rm). Asks first unless -y.

Hyper-V uses checkpoints; libvirt takes external disk snapshots (restoring needs libvirt 9.9 or newer); macOS clones the disk files on APFS, which is instant and takes no space until they differ.

vmynt blueprints

available

List the blueprints visible from here and where each comes from, or make your own.

usage
vmynt blueprints [--json]
vmynt blueprints new <name> --from <blueprint>
new <name> --from <blueprint>
Copy a blueprint into .vmynt/blueprints/<name>/ to edit.

vmynt hash

available

Make a SHA-512 crypt hash of a password, for passwordHash. Asks for the password without echoing it.

usage
vmynt hash

vmynt doctor

available

Check this computer is ready: hypervisor, permissions, ssh, desktop client. The last check connects to the hypervisor exactly as create will. Prints a fix for each failure and exits non-zero if something required is missing.

usage
vmynt doctor

vmynt clean

available

Delete cached installers and files left over from failed builds. Asks first unless -y.

usage
vmynt clean [-y]

vmynt completion

available

Print a shell completion script.

usage
vmynt completion bash|zsh|fish|powershell

See Shell completion.

vmynt version

available

Print the version, commit, build date and platform. The same as vmynt --version.

usage
vmynt version [--json]

vmynt help

available

List every command, or explain one. vmynt on its own, -h and --help do the same.

usage
vmynt help [command]
