Vmseed / Roadmap

Roadmap

Vmseed is the Rust rewrite of a PowerShell tool that built these VMs on Windows. Milestones M0 to M3 are done: every command works on Hyper-V, KVM and Apple Virtualization. M4, the road to 1.0, is under way.

The full plan is in the repository's design document.

M0: Skeleton and release pipeline

done
  • Every command in the CLI, with help, -v/--version, shell completion and typo suggestions
  • Config loading, layering and quick settings
  • Built-in blueprints and vmseed blueprints / blueprints new
  • vmseed init, the full flow, with password hashing
  • hash, config, doctor, clean, the project registry
  • Releases through winget, Chocolatey, Homebrew, apt and GitHub Releases, with versioning and changelog automation

M1: The VM commands and Hyper-V

done
  • Full config resolution and validation: blueprint defaults and overrides, data disks, database, files, hooks, repos, SSH keys
  • Installer download with SHA-256 verification and a cache; the seed disk built in-process (no admin rights)
  • The Hyper-V backend
  • create, start, stop, restart, poweroff, remove, open, ssh, exec, logs, status, live list, snapshot
  • Vmseed's own SSH key in every VM, so ssh and status need no setup
  • Still to come: the first pass on real Hyper-V hardware

M2: Linux and KVM

done
  • The libvirt backend, with disks in a storage pool and snapshots
  • Guest tools and remote desktop over TCP for KVM
  • Opening the desktop with FreeRDP or Remmina, the console with virt-viewer
  • .deb and .rpm packages, and a nightly end-to-end build in CI

M3: macOS and arm64

done
  • The vfkit backend on Apple Virtualization, with APFS-clone snapshots
  • arm64 installers for every blueprint, and Chromium where Chrome has no arm64 build
  • Opening the desktop in Windows App
  • Still to come: the first pass on a real Mac

M4: 1.0

in progress
  • Done: blueprints are YAML (blueprint.yaml, camelCase keys like the config files)
  • Done: the PowerShell tool is removed; Vmseed is the only tool
  • Code signing, ready and waiting for certificates: Windows binaries through Azure Artifact Signing, macOS binaries with a Developer ID certificate and notarization. Each turns on once its account is set up.
  • Every release carries GitHub build-provenance attestations. Check a download with gh attestation verify <file> --repo scarlettiron/vmseed
  • Still to come: real-hardware passes on Hyper-V and on a Mac
  • Still to come: the first stable release

Later

  • Blueprints downloadable on their own, instead of all built in
  • A second backend per OS, such as QEMU on macOS, through the hypervisor setting

Not planned for 1.0: Windows guests, remote hosts and cloud providers, and a graphical app. Ideas and help are welcome on GitHub.
