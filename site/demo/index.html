Vmynt / Demo

Demo

What working with Vmynt looks like in a terminal. Each demo plays when you scroll to it; press Replay to watch it again.

These are demonstrations, not recordings. They follow the program's real output, shortened where a build prints a lot. Names, addresses and timings are examples, and exact wording may differ between versions.

vmynt init

available

Set up a project: a name, a blueprint and your user, then the .vmynt/ folder is written and the project registered. How init works.

~/work/acme 
$ vmynt init
? Project name: acme
? Blueprint: ubuntu-desktop
? Username: dev
? Full name: Developer
? Password: ********
? Save as your default user? Yes

✔ .vmynt/vm.config.yaml          shared, commit it
✔ .vmynt/vm.config.local.yaml    yours, git-ignored
✔ .vmynt/vm.config.example.yaml  every option
✔ .vmynt/vm.config.local.example.yaml
✔ .vmynt/ssh_keys/               drop .pub files here
✔ .vmynt/.gitignore
✔ registered "acme" in ~/.vmynt

Next: check it with vmynt config --validate, then build the VM with vmynt create.

vmynt blueprints

available

List the blueprints, then copy one into the project to make your own. Your own blueprints.

~/work/acme 
$ vmynt blueprints
NAME                      SOURCE     DESCRIPTION
fedora-workstation        built-in   Fedora + GNOME Workstation, provisioned as a dev workstation
redhat-rhel-workstation   built-in   Red Hat Enterprise Linux + GNOME Workstation (needs your own ISO and a subscription)
redhat-rocky-workstation  built-in   Rocky Linux + GNOME Workstation, provisioned as a dev workstation
ubuntu-desktop            built-in   Ubuntu LTS + GNOME desktop, provisioned as a dev workstation
ubuntu-server             built-in   Ubuntu LTS, headless, same dev toolchain
$ vmynt blueprints new my-rocky --from redhat-rocky-workstation
✔ copied redhat-rocky-workstation to .vmynt/blueprints/my-rocky/
  set blueprint: my-rocky in .vmynt/vm.config.yaml to use it

vmynt --help and --version

available

Every command, grouped, with its aliases. -v, -V and --version all print the version. Command reference.

terminal 
$ vmynt --help
Reproducible dev VMs from a config file

Usage: vmynt <command> [name] [options]

Project
  init        Create .vmynt/ config in this folder
  config      Show the merged config; --validate to check it

Lifecycle
  create      Build the VM from config  (new, build)
  start       Start or resume; never provisions  (up)
  stop        Shut down, keeping the disks  (halt, down)
  restart     Stop, then start
  poweroff    Stop every VM on this computer
  remove      Delete the VM; --delete-disks removes its disks too  (rm, destroy)

Use
  open        Open the desktop; --console for the raw console  (desktop, console)
  ssh         Open a shell in the VM
  exec        Run one command in the VM
  logs        Show bootstrap and post-start logs

Inspect
  list        Every VM on this computer, with status and URLs  (ls)
  status      Full detail for one VM  (info, describe)

Snapshots
  snapshot    Create, list, restore or delete snapshots

Tools
  blueprints  List blueprints, or make your own with `blueprints new`
  hash        Make a password hash for the config
  doctor      Check this computer is ready to run VMs
  clean       Delete cached ISOs and leftover build files
  completion  Print shell completion for bash, zsh, fish, PowerShell or elvish
  version     Print the version
  help        Help for any command

Global options
  -v, --version   Print the version [alias: -V]
      --json      Machine-readable output (list, status, config, version, blueprints...)
      --no-color  Plain output without colors (NO_COLOR is honoured too)
  -q, --quiet     Print errors only
      --verbose   More detail, and the full cause chain on errors
  -y, --yes       Answer yes to every confirmation, and never prompt
  -h, --help      Print help

Run `vmynt help <command>` or `vmynt <command> -h` for a command's options.
Docs: https://scarlettiron.github.io/vmynt/
terminal 
$ vmynt --version
vmynt 0.1.0 (a1b2c3d 2026-10-13, x86_64-pc-windows-msvc)
$ vmynt version --json
{ "commit": "a1b2c3d", "date": "2026-10-13", "name": "vmynt", "target": "x86_64-pc-windows-msvc", "version": "0.1.0" }

vmynt doctor

available

Checks this computer before you build anything. This run is on Linux; Windows and macOS check their own hypervisor and tools. The last line connects to the hypervisor the way create will.

PowerShell 
$ vmynt doctor
Vmynt doctor  (linux x86_64)
✔ ssh                    /usr/bin/ssh
✔ data folder            ~/.vmynt
✔ KVM                    /dev/kvm
✔ libvirt                virsh found
✔ permission             member of the libvirt group
✔ UEFI firmware          /usr/share/OVMF
✔ RDP client             /usr/bin/remmina
✔ hypervisor             libvirt/KVM answers

vmynt create

available

vmynt list

available

Every VM on this computer, from any folder, with its state from the hypervisor. --live adds database and bootstrap columns.

api-ubuntu-server    not created  ubuntu-server             http://api-ubuntu-server.local    —                                        ~/work/api
oldbox               missing      fedora-workstation        —                                 —                                        ~/old/proj (folder gone)
