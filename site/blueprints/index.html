Vmynt / Blueprints

Blueprints

A blueprint is one operating system and how to install it unattended. The VM you get is "this blueprint, plus your config", and the same config on a different blueprint gives you the same dev environment on a different OS.

Every guest is Linux. List what's available from where you are with vmynt blueprints.

Built-in blueprints

The name says the family first, then the distribution: redhat-rocky is compatible with Red Hat and installs Rocky.

redhat-rocky-workstation

Rocky Linux 9 + GNOME. Rocky Linux with the GNOME Workstation environment. A binary-compatible rebuild of Red Hat Enterprise Linux with public installers and repositories, so it downloads and verifies like anything else. The machine to use if you deploy to RHEL servers. Supported to 2032. Kickstart

redhat-rhel-workstation

Red Hat Enterprise Linux + GNOME. The real RHEL. Its installers are behind a Red Hat account, so you supply your own ISO, and the VM registers with your subscription (an activation key or a username and password) before it can install packages. Kickstart

fedora-workstation

Fedora + GNOME. Fedora Workstation: the newest GNOME and toolchain. No long-term support; each release lasts about 13 months. Kickstart

ubuntu-desktop

Ubuntu LTS + GNOME. Ubuntu 24.04 LTS with the GNOME desktop, supported to April 2029. cloud-init

ubuntu-server

Ubuntu LTS, headless. The same Ubuntu release and the same dev toolchain, without a desktop. Good for databases and services alongside a desktop VM. cloud-init

Kickstart blueprints are installed by Anaconda from a seed disk labelled OEMDRV; cloud-init blueprints read theirs from a disk labelled CIDATA. Either way the install needs no clicks.

What's in a blueprint

blueprints/redhat-rocky-workstation/
blueprint.yaml          # the OS, where its installer comes from, how to seed it; an arm64 block for arm64
seed/ks.cfg.tmpl        # the unattended install answers, with {{PLACEHOLDERS}}
bootstrap/              # steps and files only this OS needs
  assets/xrdp-startwm.sh
  assets/45-allow-colord.rules

The installer is downloaded once, checked against the distribution's published checksum, and cached in ~/.vmynt/isos. The answer file is filled in from your config: hostname, user, password hash, locale, keyboard, timezone, packages.

blueprint.yaml uses camelCase keys, like the config files: os (the distribution and which versions it accepts), media (where the installer and its checksum file are), provisioning (the seed template, the disk label, the bootstrap folders), firmware, packages, and defaults and overrides for config values. A blueprint can inherits: another and state only the difference.

blueprint.yaml (part)
name: 'redhat-rocky-workstation'
description: 'Rocky Linux + GNOME Workstation, provisioned as a dev workstation'
os:
  vendor: 'rocky'
  version: '9'
media:
  isoBaseUrl: 'https://download.rockylinux.org/pub/rocky/{Release}/isos/x86_64/'
  checksumFile: 'Rocky-*-latest-x86_64-boot.iso.CHECKSUM'
provisioning:
  method: 'kickstart-oemdrv'
  seedTemplate: 'seed/ks.cfg.tmpl'
  hyperVPackages: ['hyperv-daemons']   # added to packages on Hyper-V only
packages:
  - '@^workstation-product-environment'
  - 'openssh-server'

provisioning.hyperVPackages lists the Hyper-V guest tools. They are added to packages only when the VM runs on Hyper-V; anywhere else they would hold up every boot waiting for a Hyper-V device.

Provisioning steps

After the OS installs, the VM runs a shared set of numbered bash steps on first boot, in order. Every blueprint uses them, and each step skips itself when your config turns it off. vmynt status shows the progress, and vmynt logs the detail.

How a blueprint is found

Vmynt only ever asks for a blueprint by name, and takes the first match:

  1. <project>/.vmynt/blueprints/<name>/: your project's own, committed with it
  2. ~/.vmynt/blueprints/<name>/<version>/: downloaded blueprints (empty for now)
  3. built into Vmynt

So a project can override a built-in blueprint by giving its copy the same name.

Your own blueprints

terminal
vmynt blueprints new my-rocky --from redhat-rocky-workstation

This copies the built-in blueprint into .vmynt/blueprints/my-rocky/. Set blueprint: my-rocky in your config (vmynt init's Create my own… option does both for you) and change whatever you need: the package list in the answer file, an extra provisioning step, a different installer. Anything your copy doesn't contain falls through to the shared steps.

arm64 and Apple Silicon

Macs with Apple Silicon run arm64 guests only, and arm Linux hosts can too. The guest's architecture follows the computer's unless you set arch: in the config. Each blueprint has an arm64 block naming its arm64 installer, laid over the rest of the blueprint when the guest is arm64: blocks merge key by key and lists replace. It also sets provisioning.hyperVPackages: [], since there are no Hyper-V guest tools for arm64.

PartOn arm64
Rocky, Fedora, Ubuntuarm64 installers are published
RHELarm64 exists, behind a subscription, as on x86_64
Google ChromeNo Linux arm64 build; Chromium is installed instead (the snap on Ubuntu, the package on Fedora and the RHEL family), and vmynt status says which browser you got
VS Code, Node, Python, Docker, ddev, Postgres, MySQLAvailable for arm64
Postman, mkcert, direnvThe arm64 build is picked automatically
PostgreSQL on FedoraThe PostgreSQL project has no Fedora arm64 repository, so Fedora's own package is used, with a warning if its version differs

A custom blueprint without an arm64 block refuses to build an arm64 guest and says so.

Downloadable blueprints

All blueprints are built into Vmynt for now; together they are about 350 KB of text. The big downloads are the OS installers, and those are only fetched for the blueprint you use. A later release will let blueprints be downloaded on their own, into ~/.vmynt/blueprints, without changing how you name them.
